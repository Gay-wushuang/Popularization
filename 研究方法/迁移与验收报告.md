## 6. 独立一轮架构复核

此处“独立”指完成初稿后单独一轮、以反例为中心的复核，由同一执行者完成，不冒称另一位专家或外部评审。以下均为假设性桌面检查，不产生实际研究数据。

| 复核方向／假设情境 | 发现与处置 | 复核判断 |
| --- | --- | --- |
| 匿名传闻被多处转载 | 来源独立性与传播根源单列；帖子存在和事件成立拆开；LEAD 不自动升级 | 可阻止热度替代证据 |
| 软件代码存在但评测未运行 | 来源、实现、实验状态、部署影响分开；无输出标未执行 | 可保留失败与未决，不补造结果 |
| 平台便利样本被解释成社会民意 | 两份调查模板记录总体、样本框、有效分母、推荐与非响应偏差 | 禁止越界外推 |
| 纯形式研究被迫实验或寻找社会因果 | 初稿虽允许形式验证但缺操作卡；补 M18 形式证明与模型验证 | 修复验证方法缺口 |
| 小题必须建立所有对象和多张表 | 明确只在需引用时分配 ID，可一文分节，描述研究可不建 HYP／INT／DATA | 降低流程成本 |
| 项目多份规范、真伪结论漂移 | 全局主规则、SRC 真伪主记录、矩阵关系、分析和结论各有唯一位置 | 避免重复维护 |
| 新项目目录或成果被历史学绑定 | 不强制配音史目录、视频、实验、统计或因果；配置决定方法标准 | 接入无需改全局规范 |
| 公开分支或匿名化被当私密保护 | 明确任何公开仓库分支不隔离，化名不保证匿名，受限原件仓库外 | 修复表达歧义 |
