# 证据链与辩证论证规范

版本：V1.0.1；日期：2026-11-10；适用见[全局入口](README.md)，本轮修订状态见[根说明](../README.md)。编号、证据关联、论证、修订和版本规则以本文为准。

## 1. 作用域与分配

完整编号为 `项目代码-类型-六位流水号`，如 `DEMO-SRC-000001`；DEMO 仅演示，不占用项目代码。代码在[根登记表](../README.md)查重登记，类型各自计数。专题为 `项目代码-T-四位流水号`，不嵌入对象编号：来源跨专题复用不换 ID。位数不足时扩位，不回绕。

| 类型 | 对象与主位置 |
| --- | --- |
| LEAD | 调查线索：线索登记 |
| SRC | 已定位而真实性可待核验的来源：来源登记 |
| CLM | 可单独核验的描述、比较、因果等主张：证据矩阵 |
| HYP | 待检验解释与预测：分析记录 |
| INF | 有明确前提和结论的推理步骤：分析记录 |
| EVT | 事件及时间精度、证据与冲突：时间线或登记簿 |
| ENT | 人物、机构及其他实体、别名和身份时段：实体记录或登记簿 |
| DATA | 原始／处理后数据集或实验数据版本：数据实验记录 |
| INT | 一次访谈或口述活动：访谈记录 |
| CONCLUSION | 综合判断与发布结论：结论复核 |
| REV | 重要质询、纠错与修订：修订记录 |

每项目由负责人或登记人维护一份登记簿，首条实际对象出现时才创建；可由配置或总览中的表承担，不强制数据库。字段为完整 ID、类型、标题、主路径和锚点、关联专题、分配人和时间、在用／合并／废弃状态、替代或关联 ID。

分配前查登记簿和项目全部记录，按同类型最大已分配号加一，保留号也计入。并行工作先由登记人分配不重叠号段，合并时查重，不各自从 1 开始。重复时保留已引用 ID，冲突新记录另分配并记映射、修正引用。合并相同来源保留主 ID 和旧 ID 重定向；废弃、误分配和撤回的编号不得复用。

跨项目以完整 ID 和主位置引用，不复制后当独立证据；权限隔离时只共享许可元数据。新调查或不同版本另记对象与关系。EVT 编号不使未证事件成为事实；ENT 须检查同名、角色时段与隐私限制。

## 2. 线索到结论的关联

导航为 `LEAD → SRC → CLM → HYP → INF → CONCLUSION`，不是自动升级或强制单线。来源可对应多命题，描述研究可不建 HYP，实验可从 HYP 出发，反证可返回 LEAD；对象不因关联而改 ID 类型。

每一箭头写明依据：线索找到何材料；材料哪个位置作用于哪个主张；主张是什么前提；假说预测什么；推理规则与假定；结论依赖哪些 INF、CLM。INT 的录音／转录、DATA 的采集／结果同时关联 SRC 或可定位原件，不能只有活动编号没有证据内容。

不同类型只在需要单独引用时分配。同一假说或推理不为填表重复编号；HYP 关联其可检验预测的 CLM，INF 关联其输入与输出。小型描述研究不必建立 HYP、DATA 或 INT。

每条命题证据记录至少含 CLM、SRC／DATA／INT、具体位置或版本、摘录／观察值、证据方向、证据关系、独立性及依赖组、推理用途与局限。方向与关系的取值和定义统一见[信源规范第 2 节](02-信源分类与评价规范.md#2-必须分开的评价维度)，不能以来源已核验或独立代替这两项判断。真实性只在 SRC 主记录维护，矩阵引用它，避免互相冲突的副本。事件时间、来源形成时间和公开时间分开，保留区间与估计依据。

来源之间的冲突另记双方 SRC 与具体位置、涉及 CLM、可比范围及核查处置；它不等同于单条证据反驳 CLM。采用[矩阵模板](../模板/08-主张与证据矩阵.md)的独立区块或链接已有冲突记录，不把两个维度重新合并成“存在冲突”。实际旧记录迁移保留原分类、原版本和修改理由，重要判断变化关联 REV；历史归档不重写。

## 3. 辩证与因果分析

1. 明确问题、拆分命题，标记事实描述、解释、推论、假说或观点。
2. 建立可核验事实基础，分开已知、冲突与缺失，不把资料断言直接当事实。
3. 分析制度与实践、模型与观测、能力与应用、意图与接受、连续与变革等关系；检查矛盾是否只是对象或定义不同。
4. 因果命题逐段说明时间、机制、证据、条件和混杂；区分必要、充分、促进／抑制、背景和伴随因素，不只列因素或凭前后顺序断言因果。
5. 列竞争解释及各自预测、区分证据；相容解释可共同成立，不制造阵营。
6. 主动查反证，记查询、渠道、日期、结果、缺失范围与处置理由；没找到反证不等于证明成功。
7. 限定范围及修订条件。经验命题说明可检验反例；形式命题用证明检查或反例；价值观点说明规范前提，不强加同一种证伪形式。

反事实注明思想实验属性，基于当时／该系统的可行选择与约束，不当直接事实。证据不平均分权；可得单一解释较优、多因素作用、分阶段成立或无法判断。

## 4. 多维验证与负证据

| 验证项 | 操作与边界 |
| --- | --- |
| 真实性、出处、作者主体 | 核对原件、身份、版本与转引，未取得则限定层级 |
| 形成、事件、公开时间 | 比较日期、时区、版本及时间线冲突 |
| 依赖与多源独立核验 | 追踪共同来源、样本、采访或数据，不计页面数量 |
| 反证与竞争解释 | 查相反资料和区分性预测，说明排除理由 |
| 数据、实验与证明 | 按所选方法核对原始数据、环境、步骤、对照或推导 |
| 范围与代表性 | 查总体、样本框、缺失、平台和组织偏差，不越界外推 |
| 不确定性 | 列测量、记录、模型、选择和解释误差及影响 |

没有找到记录不自动证明事件未发生。只有说明若发生应留下何种记录、记录形成保管制度、检索覆盖和缺失可能，才能评估负证据作用。档案缺失、保存偏差、不公开或尚未数字化可能削弱否定推论。

## 5. 判断与修订

结论置信程度为高／中／低／未决并附理由：高表示关键依据可靠适用、依赖已检查、重大反证已处理；中表示较强支持但有限制；低表示关键环节间接或缺失；未决表示不足以判断或区分。没有全局来源数量阈值或总分，也不能冒充统计概率。

论证处置另用保留／修订／撤回／未决；来源真伪、证据方向、证据关系、独立性和结论置信不得合成单一等级。

重要修改记 REV：原对象与版本、触发材料、新旧判断、理由、人和时间、影响成果、后续任务及版本位置。错别字可由 Git 差异说明，改变证据或判断强度须留修订记录；原始资料不被分析覆盖。

## 6. 文件版本与 Git

正式记录有 ID／项目专题、负责人、日期、所据规范版本、仓库相对路径或受限保管位置。来源记录保留原始 URL／标识与具体定位，推理及结论通过证据关系回溯这些位置，不重复抄写全部书目信息。文档版本号供阅读，内容定位用完整 Git SHA 和提交内路径／锚点；可在总览集中登记，不必每表重复抄 SHA。

新记录标“工作副本，未提交”，不得用 HEAD 冒充包含新内容的提交。获授权提交后，在后续版本清单记包含记录的完整 SHA、路径和版本；文件不能在同一提交中填该提交自身最终 SHA。未获授权就保持未提交，可用哈希辅助核对，不能称已 Git 冻结。

引用既有记录用固定提交，不以变化的分支名替代。SHA 只定位版本，不证明来源真实或判断正确。外部原件记标识、获取时间、校验值；私有原件保留受控复核方式，不强行进入公开历史。
